# Задача: написать сценарий комедийного ролика на новую тему

Ты работаешь в репозитории `kodeksdeneg`. Есть вечерний автопилот
(`daily-comedy-post.mjs`), который каждый вечер публикует один короткий
комедийный ролик в формате «злодей проигрывает» (в духе Тома и Джерри) —
не пересказ статьи сайта нейтральным голосом, а короткая сценка с
сюжетом, шуткой и твистом, которая всё равно доносит настоящий
юридический совет. Пилотный ролик (тема дипфейк-голоса) уже одобрен
Ником 14.09.2026 — см. `PILOT` в `scripts/social/generate-comedy-short.mjs`,
он и есть образец стиля/структуры.

## Шаг 1 — проверь, нужно ли что-то делать

Прочитай `scripts/social/posted-comedy.json` (массив уже опубликованных
slug'ов). **Если файла нет или он пустой** — это первый прогон, ничего
не делай и заверши работу: `daily-comedy-post.mjs` сам возьмёт `PILOT` из
`generate-comedy-short.mjs` по умолчанию.

Если файл не пустой — переходи к шагу 2.

## Шаг 2 — выбери следующую тему

Только раздел **мошенничество** (`content/topics/moshennichestvo.mjs`) —
самые «болезненные» темы, про которые Ник просил в первую очередь. Возьми
первую тему по порядку в файле, чей `slug` **ещё не встречается** в
`posted-comedy.json` и не совпадает с `PILOT.slug`. Если все темы раздела
уже использованы — возьми любой другой раздел сайта (`content/topics/*.mjs`)
по такому же принципу, самую близкую по духу к «реальная схема
обмана/острая денежная проблема».

Прочитай реальный контент темы (`sut`, `law`, `first`, `steps`, `dont`) —
сценарий должен опираться на настоящие факты темы, не выдумывать новых.

## Шаг 3 — напиши сценарий

Структура — 6 сцен (как в `PILOT`), каждая — объект
`{ bg, emoji, headline, bubble, narration, domain? }`:

1. **Интро с маскотом** — `emoji: '💰'`, `headline: 'Рублёнок рассказывает'`,
   `bubble` — короткий тизер темы, `domain: 'kodeksdeneg.ru'`,
   `narration`: «Рублёнок — герой проекта «Кодекс денег» — сегодня
   показывает [суть схемы].»
2. **Злодей хвастается/готовит схему** — эмодзи-персонаж мошенника (не
   привязывай к конкретной национальности/этносу — обобщённый
   карикатурный жулик, см. правило ниже), что он собирается сделать.
3. **Схема в действии** — сама попытка обмана, максимально по реальному
   механизму темы.
4. **Твист — жертва не поддаётся** — конкретная деталь, которая ловит
   мошенника (из реального `first`/`law`/`dont` темы, не выдумка).
5. **Мошенник проигрывает** — комедийная развязка, коротко и хлёстко.
6. **Payoff + сайт** — реальный совет читателю (из `first`/`steps` темы) +
   `domain: 'kodeksdeneg.ru'` в бабле + narration заканчивается: «Рублёнок и
   подробный разбор — на сайте кодекс денег точка ру.»

`bg` — CSS `linear-gradient` (можно взять готовые примеры из `PILOT`,
меняя оттенок под настроение сцены — тёмный/тревожный для мошенника,
светлый/уверенный для победы).

## Что НЕ делать — категорически

- Не привязывай злодея к реальной национальности, этносу, полу,
  профессии реальной группы людей — только обобщённый карикатурный
  «жулик» (шляпа, тёмные очки, эмодзи 🕵️/🤖/🎭 и т.п.), без стереотипов.
- Не выдумывай юридические факты — только то, что реально написано в
  теме сайта (`law`, `sources`).
- Не копируй текст темы дословно в `narration` — перескажи как реплики
  персонажей и рассказчика, живым разговорным языком, коротко (весь
  ролик — 45-60 секунд озвучки, это ~110-140 слов суммарно на все 6 сцен).
- `narration` пишется для озвучки TTS — простые предложения, без
  сокращений и цифр цифрами (пиши «десять секунд», не «10 секунд» — в
  `bubble`/`headline`, наоборот, цифры можно, это текст на экране, не
  озвучка).

## Куда сохранить

Запиши получившийся объект в файл `scripts/social/comedy-script.json` —
**один JSON-объект** вида (не массив — `daily-comedy-post.mjs` читает
файл как один объект и берёт `scriptData.slug` напрямую):
```json
{ "slug": "<slug-темы>", "title": "<короткий цепляющий заголовок для YouTube, до 90 символов>", "scenes": [ ... 6 объектов ... ] }
```

Не запускай рендер и не публикуй сам — это сделает следующий шаг
workflow (`daily-comedy-post.mjs`). Не трогай `posted-comedy.json` — его
обновляет сам скрипт после успешного рендера.

## Описание к посту (caption) — делает сам рендер, не ты

Текст описания под видео (YouTube/Facebook) собирается автоматически
внутри `renderComedyVideo()` (`buildComedyCaption()` в
`generate-comedy-short.mjs`) — он сам подтягивает настоящий контент
темы сайта (`sut`/`first`/`steps`/`law`/`dont`) по `slug`, который ты
указал в `comedy-script.json`. **Правило проекта (Ник, 14.09.2026):
описание должно быть не короче 1000 символов и уникальным** (не общий
шаблон на все видео) — это уже гарантировано автоматически, пока
`slug` в твоём сценарии — реальный `slug` темы сайта из
`content/topics/*.mjs`. Именно поэтому важно шаг 2 выше выполнять
точно: если `slug` не найдётся среди реальных тем, описание соберётся
из текста самого сценария (headline/bubble/narration сцен) — тоже
рабочий вариант, но менее содержательный, чем настоящая статья темы.
Тебе НЕ нужно самому писать `caption`/`description` в
`comedy-script.json` — только `slug`, `title`, `scenes`.
